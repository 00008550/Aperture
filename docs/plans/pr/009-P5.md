## What this portion does

Adds `ScopeRlsEquivalenceTests` (test-only) — the honesty pin for the whole RLS redesign. The scope
rule is now encoded in several places, and this test proves, at the DBMS on identical adversarial
data, that they all select the **identical id set**:

1. the in-memory reference oracle — `DataScopeSet.Admits` (001-P1);
2. the EF expression — `WhereInScope<T>()` (001-P4), run through the **owner** role (RLS bypassed,
   so the predicate is the only filter);
3. the P2 SQL fragment — `ToSqlFragment` (009-P2), run through the owner role with only the fragment
   in the `WHERE`;
4. the RLS `USING` policy (009-P3), run through the least-privilege **`aperture_reader`** role with
   an unfiltered `SELECT`, so the policy is the only filter;
5. the production door — `ScopedConnection` (009-P4), fragment **and** RLS together.

Each SQL encoding is asserted equal to the independent in-memory oracle, so agreement on a *wrong*
answer is caught, and any pairwise drift follows by transitivity. Assertions are order-independent
set equality over sorted id arrays — not row counts.

Cases: every scope kind (Self, Team, Region, Account, AllTenant), two unions, an
AllTenant-subsumes-Team overlap, and the empty set (which must return nothing in every encoding).

## Adversarial seed

Two tenants that **reuse the same** user/team/region/account GUID values; rows with NULL
team/region/account; rows matching more than one grant at once (union dedup); a foreign-tenant row
that matches every grant value; and a foreign-tenant row carrying the principal''s own owner id
(proving the tenant term beats an owner match). The reader-role leg exercises real RLS.
