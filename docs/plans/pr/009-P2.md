## What this portion does

Builds the raw-SQL sibling of `ScopeQuerying.ToPredicate<T>()`: `DataScopeSet.ToSqlFragment(columns)`
returns a `ScopeFragment` — a `WHERE` fragment plus a parameter bag — so a future Dapper read can be
scoped without the developer hand-writing (and forgetting) the tenant predicate.

- `DataScope.ToSqlFragment(ScopeColumns, ScopeParameterBag)` — a **third abstract member** beside
  `Admits` and `ToPredicateBody`, so a new scope kind fails to compile until it says how it filters
  in SQL. `Self`/`Team`/`Region`/`Account` emit `{column} = @param`; `AllTenant` emits `TRUE`. Every
  scope value is bound via the parameter bag; nothing is inlined.
- `ScopeSql.ToSqlFragment` — composes `({alias}.tenant_id = @tenant) AND (…grant union…)`. The
  tenant term is conjoined **outside** the parenthesised union and cannot be OR-ed past, including by
  `AllTenant`. The empty set yields `… AND (1 = 0)` — decided before any grant is bound — with the
  tenant parameter still present so the fragment is executable and matches nothing.
- `ScopeColumns` — alias + five column names, each validated at construction against
  `^[A-Za-z_][A-Za-z0-9_]*$`. The alias/column names are the only caller-supplied text that appears
  inline; a malformed one is an `ArgumentException`, never a sanitised string.
- `ScopeFragment` — `Sql` + `IReadOnlyDictionary<string, object?>` parameters (keyed without `@`).
- `ScopeParameterBag` — alias-scoped parameter names (`__scope_{alias}_tenant`, `__scope_{alias}_pN`)
  so two fragments with different aliases AND-ed into one query cannot collide.

## Reviewer judgment calls (ruled sound)

- Alias-scoped parameter names diverge from the plan's illustrative `@__scope_tenant`/`@__scope_p0`
  literals, but the plan's edge 8 requires the prefix/ordinal be caller-scoped — the builder chose
  the prefix. Edge 8 holds by construction and is asserted.
- The empty-set bag keeps the tenant parameter: the `@__scope_a_tenant` placeholder is present in the
  SQL, so dropping its bound value would make the query fail to execute. `1 = 0` guarantees it still
  matches nothing.
