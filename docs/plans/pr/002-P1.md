# 002-P1 — Sales module foundation + the owed reader-role DI wiring

Plan: [`002-sales-accounts-contacts-deals.md`](../002-sales-accounts-contacts-deals.md), portion P1.
Roadmap: ARCHITECTURE.md §13 item 002 (Sales), and the raw-SQL read path from 009 reaching its first consumer.

## What this portion does

Stands up the Sales module skeleton and pays the DI debt 009-P4 flagged: the reader
`NpgsqlDataSource` + `ScopedConnection` are wired into the API host for the first time.

- **Sales module skeleton** owning the `sales` PostgreSQL schema: `SalesModule.AddSalesModule`
  (single public surface, internals `internal`), `SalesDbContext` (maps `sales` only), the
  module''s **own** `ITenantOwned` marker (deliberately not shared with Access), and
  `SalesNpgsqlOptions` pinning the module-owned `sales.__migrations` history table.
- **Tenant query-filter convention** copied verbatim from Access: applied by reflection over
  `ITenantOwned` in `OnModelCreating`, closing over `this` so the tenant is read per query, never
  captured into the cached model. A convention test asserts it in both directions and by an
  assembly-scan agreement check — trivially empty now, load-bearing the moment P2 adds `Account`.
- **`InitialSalesSchema` migration** creating the empty `sales` schema only. Reader
  `GRANT USAGE/SELECT` are deferred to P2, where they land per-table with `ScopeRlsPolicy.Enable`
  alongside the tables they cover — grants belong with the tables, not coupled to the Access-created
  role with no migration-ordering guarantee.
- **The owed reader-role DI wiring** (`ScopedReaderRegistration.AddScopedReader`, in the sanctioned
  `SharedKernel/Data` wrapper): the reader `NpgsqlDataSource` (singleton — owns the pool) and
  `ScopedConnection` (scoped — per-request handle). The reader connection string is **distinct**
  from the EF owner (username `aperture_reader`, not `aperture`), and the `aperture_reader` password
  is sourced from `Aperture:ReaderPassword` (a deploy secret) and merged onto a credential-free base
  string via `NpgsqlConnectionStringBuilder`, never string-concatenated and never committed. Building
  the data source opens no connection, so an absent secret does not stop the host booting; the reader
  cannot authenticate until the secret is provided (fail-closed at first query, not fail-open).
- **Host subscribes to the scoped-read `ActivitySource`** so its tenant/scope-count spans actually
  materialise (a full OpenTelemetry pipeline is 008''s concern).
- **New Sales test project** wired into `Aperture.slnx` (the module had none).

Proven against a real PostgreSQL container, not asserted from the builder''s word:

- A `ScopedConnection` resolved from a built DI container authenticates as `aperture_reader` and is
  RLS-bound: an in-scope grant admits the owned row and a foreign row is denied.
- A reader connection with no established session context returns **zero** rows (fail-closed).
- The registration merges a secret-sourced password onto a credential-less base string; and with no
  password anywhere the data source still builds but the first read cannot authenticate.
- Lifetimes asserted: reader `NpgsqlDataSource` singleton, `ScopedConnection` scoped.
- The migration creates the `sales` schema and the module-owned `sales.__migrations` history table.
