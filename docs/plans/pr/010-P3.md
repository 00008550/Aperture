## 010-P3: Data layer (typed client + query hooks)

Plan: `docs/plans/010-reactive-console-experience.md` (P3). Roadmap: 010, the reactive console's Sales surface.

### What it does
- `api.ts`: hand-written types for the Sales contracts, checked field by field against `AccountModels.cs`, `ContactModels.cs` and `DealModels.cs`. Covers `Page<T>{items,nextCursor}`, `expectedVersion` (xmin), the deal/line views, `TransitionDealRequest`, `ApproveDiscountRequest`, and the `limit`/`cursor`/`includeDeparted` query params. There is one thin function per existing route.
- `apiAuthed`: the single path that handles 401/403. It drops the token with the refused-token message. `useSession` now goes through it too, so the rule exists in one place.
- `data/keys.ts`: query keys start with a resource namespace and include the access token, so users never share cache entries and prefix invalidation still works.
- `data/gate.ts`: the `useGate` fail-closed gate (an unresolved session counts as "no"). Writes with no permission reject before any fetch. `toGridModel` checks in this order: denied, then no-scope (edge 5, never widened to rows), then loading/error/empty/rows.
- `data/useAccounts|useContacts|useDeals.ts`: infinite keyset lists (a null `nextCursor` means no next page, edge 11), detail reads, and mutations that invalidate their resource namespace on success.
- There is no contact detail hook because the server has no `GET /api/contacts/{id}`. That is correct, not a gap.

API-first (invariant 5): no new endpoint and no .NET change.

### Known gap, deferred to P4/P7 (must be picked up there)
On a **409** from `POST /api/deals/{id}/transition` or `/approve-discount` (and on the PATCH account 409), the server returns the **current deal** in the body. `api()` throws `ApiError(status, message)` and **discards the response body**. The same thing happens to the `{error}` message of a 422. P4 (edge 7, stale edit) and the deal portions (edge 8, edge 9 "server's message", edge 15 conflict re-apply) need `ApiError` to keep the parsed body. P3's Done-when does not require conflict UX, so this is deferred, not blocking.
