# 002-P2 — Accounts: aggregate, tax-id dedup, write endpoints + scoped grid

Plan: [`002-sales-accounts-contacts-deals.md`](../002-sales-accounts-contacts-deals.md) · Roadmap: ARCHITECTURE.md §13 item 002 · First real Sales tables, and the first production consumer of 009's `ScopedConnection` grid path.

## What this portion does

- **`Account` aggregate** (`Sales/Domain/Account.cs`) — owner, region, credit limit, payment terms, tax id, the five denormalised scope columns (`tenant_id, owner_user_id, team_id, region_id, account_id`), `xmin` optimistic token. `account_id = id` (the account is its own scope target), stamped in the constructor and never settable from input. `ITenantOwned` + `IScopedResource`.
- **`sales.accounts` migration** — table + unique `(tenant_id, tax_id)` + `(tenant_id, created_at, id)` keyset index, and `ScopeRlsPolicy.Enable("sales","accounts")` (the reader-role GRANT + RLS deferred from P1 lands here).
- **Endpoints** (`Aperture.Api/Endpoints/AccountEndpoints.cs`), each policied: `POST /api/accounts` and `PATCH /api/accounts/{id}` on `accounts.write`; `GET /api/accounts` (grid) and `GET /api/accounts/{id}` on `accounts.read`. Tenant and owner come from the resolved principal, never the body; region/team are the account's business attributes and are the caller's to state.
- **Scoped grid** (`AccountService.ListAsync`) — keyset-paginated by `(created_at, id)` through `ScopedConnection` (reader role + RLS), opaque base64 cursor, parameterised throughout.
- **Tax-id dedup** — the unique index is the arbiter; a collision surfaces as SQLSTATE 23505 scoped to `DbUpdateException` and returns a clean 409, not a 500.

## Scope-column stamping (security note)

`tenant_id`/`owner_user_id`/`account_id` are never taken from the request body — tenant and owner come from the principal; `account_id = id`. `region_id`/`team_id` come from the body by design (they are the account's business attributes so Region/Team grants can match); RLS still filters **reads** by the viewer's own grants, so a body-set region/team cannot widen who can see a row beyond what the tenant's grants already admit. `PATCH` reassignment of owner/region/team is a deliberate `accounts.write` action.

## The one 009 wrapper edit

`ScopedConnection` gains a static constructor setting `Dapper.DefaultTypeMap.MatchNamesWithUnderscores = true`. Dapper is referenced only by this project (enforced by `RawSqlIsScopedTests`), so this is the sole home for its column-mapping config and affects only queries issued through the wrapper. It is orthogonal to the RLS/anti-bypass guarantees, which are enforced by the reader role and per-read session context — re-verified: Access's 52 tests (incl. the edge-16 hostile-SQL anti-bypass and the P5 differential equivalence cases) stay green.

## Known follow-up (non-blocking)

- A malformed/garbage `cursor` query value currently surfaces as a 500 (`FormatException`/`ArgumentException` from decode) rather than a 400. Not a security issue — the cursor is server-issued and opaque, parameterised, and RLS-bound, so a tampered cursor can only reposition the keyset within the caller's own scope; it cannot inject, skip scope, or leak rows. Worth a 400 mapping when a global ProblemDetails handler lands.
