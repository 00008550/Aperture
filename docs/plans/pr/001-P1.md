## What this portion does

The fail-closed primitives every later portion sits on (`ARCHITECTURE.md` §2, §3). In-memory only —
no schema, no endpoints, no DI registration; those are P2 and P3, and adding them here would have
put untestable code in the diff.

**Multitenancy**
- `TenantId` / `UserId` as `readonly record struct`. The cross-tenant defect class is "the right
  `Guid` passed as the wrong parameter", and the compiler removes it for the cost of two wrappers.
- `ITenantContext` has no default and no setter. `AmbientTenantContext` flows the tenant on
  `AsyncLocal`, **throws** when read unscoped, and restores the outer tenant when a nested scope is
  disposed — without that, an inner scope silently ends tenancy for the rest of the request.

**Authorization**
- `Permissions`: the one registry the API, the React console and (in plan 007) the assistant's tool
  definitions share. `orders.credit.override` is deliberately separate from `orders.confirm` —
  `DOMAIN.md` §2 requires the override to be independently grantable and recorded.
- `PermissionSet`: ordinal and immutable. Case-insensitive matching would let `Orders.Confirm` grant
  `orders.confirm`, turning a typo in a seed script into a privilege grant. Undeclared strings are
  dropped rather than stored, so removing a permission from the registry actually revokes it.
- `DataScope`: a closed hierarchy (private constructor) — `Self | Team | Region | Account |
  AllTenant` — so P4's SQL translator gets an exhaustive switch that stays exhaustive.
- `DataScopeSet`: union semantics, carrying the tenant it was resolved for. The tenant check runs
  first and **`AllTenant` cannot reach past it**. The empty set admits nothing.

## Which production failure this answers

`DOMAIN.md` §5.1 — a report showed one region's data to another, because "no regions selected" was
read as "all regions". `DataScopeSet.None(tenantId)` is a value of the same type as any other set,
and callers ask it `Admits(...)` rather than inspecting a count and deciding for themselves. Test 1
is that incident.

## Known limitation found while re-measuring

`measure.sh permissions` reports four permissions as "enforced in 1 file(s)" when the only reference
is a **test** file. It counts any `.cs` mentioning the string, so a permission that exists solely in
an assertion looks enforced. Not fixed here — P3 introduces the endpoints that make the measurement
meaningful, and it should exclude `*.Tests` at the same time. Recorded rather than silently left,
because a measuring tool that flatters the code is worse than no tool.

The same section correctly reports **13 of 17 permissions never enforced**, which is the expected
state before any endpoint exists.
