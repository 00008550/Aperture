# 001-P5 — Console: sign-in, session, permission-gated navigation

Plan: [`docs/plans/001-authorization-spine.md`](../001-authorization-spine.md), portion **P5**.
Roadmap: `ARCHITECTURE.md` §13 item 001.

## What this portion does

The React console now signs in with the bearer token 001-P3 issues, renders the session from
`GET /api/me`, disables navigation the user lacks the permission for, and shows an explicit
fail-closed empty state for a user with no data scopes.

- `frontend/console/src/auth.ts` — the token store: `sessionStorage` (dies with the tab) behind
  `useSyncExternalStore`, with fail-closed reads (a throwing/blocked storage reads as signed-out)
  and a sign-out reason that survives the token it describes.
- `frontend/console/src/SignIn.tsx` — takes the token the API already issued; it does not invent a
  parallel auth contract (a token-issuing endpoint is a server portion).
- `frontend/console/src/useSession.ts` — server state in TanStack Query, keyed on the token so a
  new sign-in cannot be answered from the previous user's cache; a 401/403 discards the token and
  returns to sign-in. `can()` is fail-closed (`?? false`).
- `frontend/console/src/Navigation.tsx` — the gate. Denied items are **disabled, never hidden**
  (no `href`, `aria-disabled`, a "locked" marker), so the product's shape stays legible and a
  permissions question does not read as a missing feature. Convenience only, not enforcement.
- `frontend/console/src/SessionPanels.tsx` — the "No data scopes granted" empty state, styled and
  stated so it can never read as loading, "no data yet", or "unfiltered" — the DOMAIN.md §5.1
  incident encoded in the UI.
- `frontend/console/src/permissions.ts` — mirrors `Permissions.cs` constant-for-constant (17),
  hand-kept until the OpenAPI document is published and this file is generated from it.

## How it was verified

`npm run build` (frontend/console): clean. `npm run test`: **11/11 passed** — the gate enables the
held permission and disables the rest (exact string, never a prefix), the no-token state shows
sign-in with no navigation, a refused token returns to sign-in, and the no-scopes state states
plainly that nothing is visible.

console gates its sections on, a route guarded by that permission answers **403** for an

the real authentication -> tenant-scope -> authorization pipeline (the same registration
extensions and `RequirePermission` as `Program.cs`, over real PostgreSQL with the real migration
and real signed tokens). The 200 half rules out an "everyone denied" false pass.

## Review note

One review finding, in test-harness code: `ApiFixture.SeedAsync` derived the tenant slug from the
full label before a `[..20]` cap, so labels >=20 chars sliced the uniquifying Guid entirely off and
collided on `IX_tenants_slug`. Fixed by capping the label to an 8-char prefix so the Guid entropy
always survives the cap; re-run green. No product code changed for the fix.

## Out of scope

No token-issuing endpoint (`POST /api/auth/token` is a server portion). No section routes exist in
the production host yet — they arrive with Sales and Orders — so `ConsoleGatedRouteTests` maps a
stand-in `/section`. The gate is UI convenience; the API is the control. `permissions.ts` is
hand-mirrored pending OpenAPI generation.
