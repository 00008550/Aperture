# 009-P3 — RLS foundation: reader role, policy convention, session context

Plan: [`docs/plans/009-raw-sql-scope-safety.md`](../009-raw-sql-scope-safety.md), portion **P3**
(revised 2026-09-01). Roadmap: `ARCHITECTURE.md` §13 — the raw-SQL half of 001's authorization
spine. **Supersedes the held PR #24's placeholder P3**, whose `/**scope**/` mechanism had a residual
fail-open (a caller could `OR`/comment the fragment away). This portion moves enforcement below the
SQL string to Postgres row-level security.

## What this portion does

Lands the structural core: scope enforcement now holds at the DBMS, not in a composed `WHERE`.

- **`AddScopeReaderRole` migration (Access)** — provisions the idempotent, least-privilege
  `aperture_reader` login role: `NOSUPERUSER NOCREATEDB NOCREATEROLE NOBYPASSRLS NOINHERIT`, created
  `LOGIN` but **without a password** (set out-of-band from a deploy secret; the test fixture sets a
  test password). Not a table owner, so it is subject to RLS.
- **`ScopeRlsPolicy` (SharedKernel `Data/RowLevelSecurity/`)** — the policy convention a scoped table
  adopts: `ENABLE ROW LEVEL SECURITY` + `NO FORCE` + a `FOR SELECT TO aperture_reader` policy whose
  `USING` predicate is the third encoding of the scope rule. Tenant equality is conjoined **outside**
  the grant union; `AllTenant` is `current_setting('app.all_tenant')::bool`; each grant kind is
  `column = ANY(string_to_array(nullif(current_setting(...,true),''), ',')::uuid[])`. Every schema/
  table/column identifier is validated `^[A-Za-z_][A-Za-z0-9_]*$` before being emitted inline.
- **`ScopeSessionContext` (SharedKernel `Data/`)** — `DataScopeSet` → six
  `set_config(name, @param, is_local => true)` statements. Setting names are compile-time constants;
  every scope **value** is a bound parameter, never interpolated. Throws (fail-loud) on a set with two
  distinct `Self` grants, which the singular `app.user_id` cannot represent.

## Why fail-closed holds (verified at the DBMS, not asserted)

`current_setting(name, true)` (missing_ok) reads an unset GUC as `NULL`. The tenant equality
`tenant_id = nullif(current_setting('app.tenant_id', true), '')::uuid` is then `unknown`, so the whole
`USING` predicate is not true and the row is denied. Confirmed on a real container:

- **No context at all → 0 rows** (edge 17), through an actual `aperture_reader` RLS policy.
- **Partial context** (tenant set, all grant GUCs unset, `all_tenant` unset) → **0 rows** — the
  `NULL::bool` disjunct does not widen.
- **Empty set** (tenant + `all_tenant=false`, empty grant strings) → **0 rows** (edge 3 execution).
- `AllTenant` in tenant A never returns tenant B's row (edge 4); `NULL` team/region/account columns
  are absent under their scope (edge 5); union of two scopes returns rows matching either.
- **Owner role bypasses RLS**, `FORCE` asserted **off** (edge 18) — EF is untouched.
- **Reader is least-privilege**: denied on an ungranted table; a hostile GUC value
  (`x'' OR 1=1 --`) fails the `::uuid[]` cast (fail-loud), it does not neutralise the predicate.
