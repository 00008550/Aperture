# 001-P6 — Audit trail for authorization decisions and mutations

Plan: [`docs/plans/001-authorization-spine.md`](../001-authorization-spine.md), portion **P6**.
Roadmap: `ARCHITECTURE.md` §13 item 001. This is the plan's final portion.

## What this portion does

Every authorization decision that denies, and every mutation, now leaves a tenant-owned audit
row carrying who, in which tenant, the permission, the scope decision, the reason and the
correlation id — and the AI assistant's calls are marked as such.

- `Domain/AuditEvent.cs` — the row. `ITenantOwned`, so it inherits the module's global query
  filter like every other table. `ActorKind` (Human/Assistant) and `AuditCategory`
  (AuthenticationDenied/AuthorizationDenied/Mutation) both start at `1`, so a default-initialised
  value is never a real one.
- `Auditing/IAuditTrail` + `AuditTrail` — the one write path. The tenant is stamped from
  `ITenantContext` (which throws when unset), never a caller-named tenant. `Record` stages the row
  on the request's unit of work so a mutation and its audit row commit or roll back together;
  `RecordAsync` persists in its own transaction, for deny paths that have no accompanying state
  change.
- `Authentication/AccessPrincipalResolver.cs` — the three post-signature authentication denials
  (inactive tenant, no membership, inactive user) now write an audit row before returning the
  denial, inside the ambient tenant scope the resolver already establishes.
- `Aperture.Api/Authorization/AuditingAuthorizationResultHandler.cs` — replaces the framework's
  result handler; on a forbidden decision it writes one row per refused permission, with the
  scope decision and correlation id, before the 403 is written. Lives in the host because only the
  host holds the final forbidden decision and the request's actor kind.
- `Aperture.Api/Authorization/AuditActor.cs` — marks a request as the assistant's via
  `HttpContext.Items`, defaulting to Human. Deliberately not a token claim: the principal is
  rebuilt from the database (001-P3), so a token cannot forge its own actor kind.
- `Persistence` + migration `AddAuditEvents` — the `access.audit_events` table, indexed on
  `(tenant_id, occurred_at)` and `(tenant_id, actor_user_id)`.
