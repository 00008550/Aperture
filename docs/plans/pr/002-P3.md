# 002-P3 — Contacts: one-account rule, departed-not-deleted, scope inheritance

Plan: [`002-sales-accounts-contacts-deals.md`](../002-sales-accounts-contacts-deals.md) · Roadmap: ARCHITECTURE.md §13 item 002 · The second Sales aggregate, a child of `Account`.

## ⚠️ This P3 PR also fixes a latent P2 (Accounts) bug — read this first

P2 shipped a **latent `DataScope.Account`-grant filtering bug on the EF path.** `Account.AccountId` was a non-nullable `Guid` with an *explicit* `IScopedResource.AccountId` implementation. `ScopeRowExpressions.For<T>` resolves scope members by reflection on the concrete type (explicit-interface members are invisible by design), so it bound the predicate to the public `Guid AccountId`, while `DataScope.Account.ToPredicateBody` builds `Expression.Equal(row.AccountId, Parameterised<Guid?>(...))`. `Expression.Equal(Guid, Guid?)` throws *"the binary operator Equal is not defined for 'System.Guid' and 'System.Nullable\`1[System.Guid]'"*. Any `DataScope.Account`-granted user hitting `GET /api/accounts/{id}` or the accounts grid via `WhereInScope` would have thrown at query build. It was latent because P2's tests exercised Self/Team/Region/AllTenant grants but not an Account grant on the EF path.

**The fix (minimal):** make `Account.AccountId` a `Guid?` (matching `IScopedResource`), drop the explicit interface member, and map it `IsRequired()` so the DB column stays **NOT NULL**. The regenerated snapshot records `Property<Guid>("AccountId")` (non-nullable) for both `Account` and `Contact`; the migration column is `nullable: false`. No data-loss/DDL beyond the new `contacts` table. `AccountService`'s `a.AccountId!.Value` is total for a persisted row (column is NOT NULL). A contact/account still cannot be persisted with a null account. The P3 edge-7 test proves an `DataScope.Account` grant now filters correctly on **both** the EF (`WhereInScope`) and RLS grid paths — it would fail to compile/translate if the property reverted to `Guid`.

## What this portion does

- **`Contact` aggregate** (`Sales/Domain/Contact.cs`) — `ITenantOwned` + `IScopedResource`. Constructed *only* from its parent `Account`: tenant and all five scope facts (`owner_user_id, team_id, region_id, account_id`) are copied from the account, never from caller input. No constructor admits a null or second account. `Depart()` is idempotent (keeps the original timestamp); there is no delete path.
- **`sales.contacts` migration** — table + parent-account FK (`ON DELETE RESTRICT`, enforcing one-account at the DB) + `(tenant_id, created_at, id)` keyset index, and `ScopeRlsPolicy.Enable("sales","contacts")`.
- **Endpoints** (`Aperture.Api/Endpoints/ContactEndpoints.cs`), each policied: `POST /api/accounts/{accountId}/contacts` and `POST /api/contacts/{id}/depart` on `contacts.write`; `GET /api/contacts` (grid, `includeDeparted` opt-in) on `contacts.read`. Turns `contacts.write`/`contacts.read` from declared into enforced.
- **Scope inheritance & fail-closed create** — `CreateAsync` loads the parent account through `WhereInScope(scopes)`, so an unknown / out-of-scope / cross-tenant account is `AccountNotFound` (404), never a leak. The contact is then built from that account.
- **Scoped grid** — keyset-paginated by `(created_at, id)` through `ScopedConnection` (reader role + RLS); active-only by default, `includeDeparted=true` returns history, both filtered below the SQL.
