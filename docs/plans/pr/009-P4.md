# 009-P4 — `ScopedConnection` revised: the only door, and it cannot run unscoped

Plan: [`009-raw-sql-scope-safety.md`](../009-raw-sql-scope-safety.md), portion P4.
Roadmap: ARCHITECTURE.md §13 — the raw-SQL half of 001's authorization spine.

## What this portion does

Lands the single sanctioned door to raw SQL and makes an unscoped raw read *inexpressible*.

- Adds the one and only `Dapper` + `Npgsql` package reference, into
  `Aperture.SharedKernel` (`Data/`). Every other project physically cannot reach
  `connection.QueryAsync`.
- `ScopedConnection` exposes exactly two read methods — `QueryAsync<T>` and
  `QuerySingleOrDefaultAsync<T>` — each of which *requires* a `DataScopeSet` and a
  `ScopeColumns`. There is no overload that omits either, no exposed raw `DbConnection`,
  and no `Execute`/write path (reads only; writes are 009 out-of-scope).
- Each read opens a **read-only transaction** as the least-privilege `aperture_reader`
  role, establishes transaction-local session context (`set_config(..., is_local => true)`)
  from the scope set via `ScopeSessionContext`, then runs the query. The caller's SQL is
  wrapped as a subquery under its named alias and the P2 fragment is `AND`-ed onto the
  outer `WHERE` as a first belt — **no placeholder, no caller-supplied WHERE splice**.
- The real guarantee is below the string: the reader role is `NOBYPASSRLS` and least-
  privilege, so every table it can read has a row-security policy. Even a caller that
  neutralises the in-app belt gets only in-scope rows.
- Observability: an activity span tagged with tenant id and per-kind scope *counts*; an
  empty scope set logs at `Information`; an unresolved (empty-GUID) tenant logs at
  `Warning`, making RLS's one new failure mode (silent zero-row read on misconfiguration)
  loud.

## How it was verified

- `dotnet build Aperture.slnx` — Build succeeded, 0 warnings, 0 errors.
- `dotnet test` Access — Passed: 43, Failed: 0, against a live PostgreSQL container.
- `dotnet test` SharedKernel — Passed: 68, Failed: 0.
- `scripts/measure.sh rawsql` — 0 production raw-SQL call sites, 41 exempt (test or sanctioned).
- `scripts/measure.sh gate` — GATE 1 pass, GATE 2 pass, GATE PASSED.
- Edge 16 (anti-bypass) proven at the DBMS: a caller that fakes its scope columns so the
  in-app belt admits every row still returns only the principal's own in-scope row — RLS
  filtered the foreign-tenant row before the belt saw it.
- Edge 19 (pooled no-leak): two reads with different scope sets forced onto one physical
  connection (`MaxPoolSize=1`) do not leak context.
- One-project Dapper rule independently re-probed: planted a second `<PackageReference
  Include="Dapper" />` in `Aperture.Worker`, `Exactly_one_project_references_the_Dapper_package`
  went red, then reverted.

## Out of scope

- Any raw-SQL write path (`Execute`, bulk insert) and its `WITH CHECK` policies.
- Rolling RLS out to real domain tables (Sales/Orders adopt the convention as they land, 002+).
- The differential EF-vs-raw equivalence test — that is P5.
